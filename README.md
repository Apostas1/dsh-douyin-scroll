# dsh-douyin-scroll ｜ 刷抖音

> **先看四行**
> - 它替你**刷一轮抖音**，把**值得看**的挑出来，写一份 Markdown 日报。
> - **不看画面**：不截图、不 OCR、不做图像识别、不做 ASR。判断只用**文案 / 标签 / 作者 / 时长 / 互动数 / 高赞评论**——全是 JSON 字段。
> - **默认不发任何评论**。自动评论是可选功能，默认关，且「@ 自己」是否成立**未经验证**。
> - 推荐采集方式：**bb-browser**（遥控你本机已登录的 Chrome）。不想装也行，`manual` 模式能立刻看效果。

---

## 它做什么 / 不做什么

| ✅ 做 | ❌ 不做 |
|---|---|
| 按关键词 / 分类 / 指定作者取候选 | 不看视频画面（无截图 / OCR / 视觉模型） |
| **代码层预筛**：文案太短且评论少、带货、太长太短、太旧 → 直接跳过 | 不做语音识别（MVP 不装 Whisper） |
| 拉**高赞评论**作为判断依据 | 不下载视频（只取元数据） |
| 用「文案 + 标签 + **互动比值** + 高赞评论」判断值不值得点开 | 不刷推荐流（抖音没有稳定的公开推荐接口） |
| 写 Markdown 日报到 `out/<日期>.md` | 不做私信（无稳定接口） |
| 可选：webhook 通知（企业微信 / 飞书 / 钉钉 / 自定义） | 不代你登录、不上传任何凭证 |
| 可选：评论区 @ 你（**默认关**，四档可插拔执行器） | 不保证判断准确（见下面「局限」） |

## 判断是怎么做的（这是最核心的部分）

抖音**没有字幕轨**可白拿（B站 有），所以不能像刷 B站 那样"读原文"。我们换成**读观众反应**：

```
第 0 层  硬过滤（纯代码，0 token）
         文案太短 且 评论少 ⇒ 跳过｜带货标记 ⇒ 跳过｜<3s 或 >10min ⇒ 跳过｜>30 天 ⇒ 跳过
第 1 层  互动结构打分（纯数值，0 token）
         关键不是点赞绝对值，而是比值：
           收藏/点赞 高 ⇒ 有保存价值（教程/攻略/美食）
           转发/点赞 高 ⇒ 想转给别人（好笑/共鸣）
           评论/点赞 高 ⇒ 引发讨论
         ⚠️ 播放量对别人的视频经常是 0 ⇒ 完全不参与计算
第 2 层  语义判断（模型）
         输入是**压缩过的证据包**，不是原始 JSON：
           文案 / 有效正文字数 / 标签 / 作者 / 时长 / 互动四件套 / 三个比值 / 高赞评论 top6
         模型必须**引用具体证据**（哪条评论、哪个比值），禁止"感觉有趣"
第 3 层  不确定就不推
         证据不够 ⇒ 进「判断不了」区，**不出现在推荐里**
```

**能区分的几类**（各自判据不同）：😂好笑 · 🛠有实用 · 💡涨知识 · 💗共鸣 · 🐱萌。
**会主动降权**：评论出现「被骗了/标题党」· 文案模板化 · 昵称带「测评/推荐」· 纯颜值 BGM（点赞高但评论空洞）。

> ⚠️ **诚实说**：这套比 B站 版弱一档。B站 读字幕全文，抖音只能读观众反应。
> 它做不到"条条精准"，但能做到"扫一眼报告，大部分值得点开"。策略是**宽松召回 + 严格推荐**：
> 点错成本很低（划过去就行），漏掉才是真损失。

## 首次使用（三步，约 2 分钟）

### 第 1 步：装主依赖
设置页点「**装主依赖**」。它会在插件家目录建一个**独立 venv**、装 `mcp` + `httpx`（走国内镜像，通常 30 秒）。
进度看 `install.log`，**不卡页面**。

### 第 2 步：选采集后端

| 后端 | 需要什么 | 能拿到什么 | 推荐度 |
|---|---|---|---|
| **`feed`** | **只要一份 Cookie**（不用浏览器） | 推荐流+相关推荐里的**完整视频对象**（文案/标签/作者/互动/时长） | ⭐⭐⭐⭐⭐ |
| `bbbrowser` | `npm i -g bb-browser` + Chromium 浏览器 + 在里面登录抖音 | 上面那些 **+ 搜索 + 高赞评论** | ⭐⭐⭐ |
| `browser` | 装浏览器依赖（几百 MB）+ 扫码 | 同 bbbrowser | ⭐⭐（重） |
| `cookie` | Cookie | ❌ 搜索/详情/评论都被 a_bogus 验签挡住 | ⭐ |
| `manual` | 什么都不用 | 你喂 JSON | ⭐⭐⭐（兜底/试玩） |

**想立刻看效果**：把采集来源切成 **`manual`**，什么都不用准备 —— 它会自动用**内置示例数据**跑一遍，
报告里会明确标注「示例」。这样你能先判断"它挑的东西合不合你口味"。

**想真刷**：
```bash
npm i -g bb-browser
bb-browser open https://www.douyin.com --json   # 应该弹出/切到你已登录抖音的 Chrome
```
然后把设置里采集来源选 **`bbbrowser`**。

### 第 3 步：填「刷什么」

- **关注关键词**：一行一个，例如 `搞笑`、`美食`、`猫`
- **推荐流分类**：例如 `游戏`、`游戏解说`（后端会拿这个词去搜）
- **指定作者**：作者主页链接或 `sec_uid`（可选）
- **每天最多挑几条**（默认 5）、**每次最多筛选几个**（默认 12）

然后点「**现在跑一轮**」。

## 用哪个浏览器？（这不是 Chrome 独占）

**内核必须 Chromium 系**（Chrome / Edge / Brave 都行）—— 因为抖音网页版只对 Chromium 正常，
bb-browser 走的也是 Chromium 的 CDP 调试协议。Firefox 不行。

bb-browser 会自动从这张表里找一个：
```
C:\Program Files\Google\Chrome\Application\chrome.exe
C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe
C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe
（以及 Chrome Dev / Beta / Canary）
```
**Edge 是 Windows 自带的** ⇒ 任何 Windows 机器都满足，不需要额外装 Chrome。

⭐ **它不碰你日常用的那个浏览器 profile**：bb-browser 起的是**独立 profile**（数据目录跟着插件走，
在 `<插件家>/bbb-home/`）。你的书签、密码、日常 cookie 它读不到。

### 想指定用哪个浏览器？
挂到你**已经开着的**任意 Chromium 调试端口即可（Edge / Brave 都一样）：
```bash
set BB_BROWSER_CDP_URL=http://127.0.0.1:9222
bb-browser daemon start --cdp-host 127.0.0.1 --cdp-port 9222
```
（⚠️ Chrome 136+ 禁止对**默认 profile** 开远程调试，所以要么用独立 profile，要么用 `--user-data-dir` 指定一个。）

### 完全不想用浏览器？
两条路都不需要任何浏览器：
- **`manual`** —— 你把候选 JSON 放进 `<插件家>/inbox/candidates.json`，插件只负责筛选和写报告
- **`cookie`** —— 粘一次 Cookie，纯 HTTP 直连（⚠️ 抖音有验签，大概率拿不到数据，属预期）

## 报告长什么样

写到 `<DSH_HOME>/douyin-duty/out/<日期>.md`：

```markdown
# 刷抖音 · 2026-10-20

> 本轮：候选 42 → 预筛 12 → 推荐 4
> 因「文案太短且评论少」跳过 9，因「带货」跳过 5，因「太旧」跳过 3
> 采集后端：bbbrowser

## 值得看

### 7401234567890123401
**加班到凌晨三点回家，猫以为我死了** · @两只猫的铲屎官 · 12 秒 · 8 小时前
🔗 https://www.douyin.com/video/7401234567890123401
📊 赞 12.8万 · 评 8600 · 藏 9000 · 转 2.1万
**为什么值得**：高赞评论 3 条都在说"笑死/绷不住"，转发/点赞 0.16 明显偏高 ⇒ 是那种会想转给朋友看的段子。
**一句话**：养猫的人看了会心一笑。

## 判断不了（没硬猜）
- 7401234567890123457 · 文案只有「嗯」，评论 1 条 —— 没有判断依据
```

⚠️ **`### <纯数字视频ID>` 这一行是宿主数配额用的** —— 这一行数 = 今天挑了几条。

## 如何关闭评论功能（默认就是关的）

三重保障，**任何一重关着都不会发**：

1. **设置里「自动评论」关着**（默认）→ 工具层直接拒绝
2. **评论执行器 = `off`**（默认）→ 即使开关开着也不会发
3. **「要 @ 谁」留空** → 不会发（评论的意义就是那一下 @）

彻底不想要它？把 `commentExecutor` 保持 `off` 就行，`duty.md` 里也写着「一个字都不要往抖音发」。

**四档执行器**：

| 执行器 | 行为 | 状态 |
|---|---|---|
| `off` | 不发（**默认**） | ✅ |
| `builtin` | 走抖音评论提交接口 | ❌ **MVP 明确不可用**（要验签票据，无稳定公开实现）——调用会如实报错 |
| `browser` | 在真实页面上填评论，**但不点发送** | ⚠️ 半自动（刻意的保守设计） |
| `http` | 转发给你自己部署的服务 | ✅ 你有自己通道时用 |

🔴 **风险（必须知道）**：
- 抖音评论区**「@ 自己」是否成立未经验证**；
- 评论以**你本人账号**名义发出；
- 频繁评论会**触发风控/限流**，可能影响你正常刷抖音。
→ 所以默认关，且有两道配额闸（每轮 / 每天）+ 随机间隔 + 内容闸。

## 消息怎么到你手上

一轮跑完，结果要**真的推到你面前**，不能只是躺在文件夹里。默认走 **Windows 通知**，零配置：

| 方式 | 行为 | 要准备什么 |
|---|---|---|
| `toast`（**默认**） | 屏幕右下角弹一条：挑到几条 + 前两条值不值得看；留在通知中心（Win+N） | **什么都不用** |
| `file` | 不额外提醒，报告落在 `out/<日期>.md` | — |
| `webhook` | 推到企业微信 / 飞书 / 钉钉群，或任意 URL（`custom`） | 一个机器人 webhook 地址 |
| `both` | 弹通知 + 推 webhook | 同上 |

设置页「通知 → **发一条测试消息**」点一下就知道通不通 —— 通了会**当场**弹到你屏幕上。

> **为什么不做「抖音私信发给我」**：发私信和搜索/评论一样要 `a_bogus` 签名，而签名是抖音页面 JS 算的；
> 在签名搞定之前这条路通不了。所以先给真正零配置、不需要任何账号授权的 Windows 通知。

## 已知局限（不掩饰）

1. **判断准确率低于 B站 版** —— 没有字幕，只能读观众反应。
2. **「文案极简 + 评论少」的视频一定会漏** —— 这是刻意的：没依据就不硬猜。
3. **播放量不可用** —— 对非作者的视频经常返回 0，所以判据里完全不用它。
4. **推荐流不可用** —— 抖音没有稳定的公开推荐接口，只能用"多关键词 + 分类词"模拟。
5. **bb-browser 的输出形状可能随版本变** —— 驱动里做了递归兜底（只要能找到带 `aweme_id` 的对象就能解析），但极端情况下可能失效；抓包摘要写在 `bbb-capture.jsonl`。
6. **`cookie` 模式大概率拿不到数据** —— 抖音有 `a_bogus`/`X-Bogus` 验签，这是设计事实，不是 bug。

## 排障

| 现象 | 看哪里 |
|---|---|
| 设置页不出现「刷抖音」 | 重启 dsh；看日志有没有 `1 entry did not activate` |
| 拿不到候选 | `douyin_whoami` / `douyin_backend`；`duty.log`；`bbb-capture.jsonl` |
| bb-browser 抓不到 | Chrome 里**先登录抖音**；`bb-browser open https://www.douyin.com --json` 试一次 |
| 报告是空的 | 宿主会补一份「占位报告」并贴日志尾部；完整日志在 `duty.log` |
| 判断太保守/太激进 | 调「文案太短阈值 / 评论少阈值」和「每次最多筛选几个」 |
| 一轮跑太久 | 降 `with_comments`（在首页的 tool 参数里）—— 拉评论是最慢的一步 |

**数据都在**：`<DSH_HOME>/douyin-duty/`（`config.json` / `duty.md` / `out/` / `inbox/` / `duty.log` / `health.json`）。

## 目录结构

```
dsh-douyin-scroll/
├── package.json / cordis.patch.yml   # 插件声明（entry id 必须 = douyin-scroll）
├── index.js                          # 宿主半端：配置/工具/定时器/headless 跑一轮/HTTP
├── client.js                         # 设置页（非 ESM 自注册脚本）
├── selfcheck.mjs                     # 本地预检
├── tools/smoke.py                    # 判断层自检（不依赖 DSH）
├── lib/
│   ├── hostdeps.mjs                  # 三级兜底取宿主依赖（桌面版 profile 的坑）
│   ├── state.mjs                     # 家目录 / 谷时窗口 / 章程记账 / Cookie 脱敏
│   ├── mcp.mjs                       # 极简 stdio MCP 客户端
│   ├── credential.mjs                # Cookie 存取（替代 B站 的扫码登录）
│   ├── notify.mjs                    # webhook + 报告摘要 + URL 脱敏
│   ├── toast.mjs                     # Windows 通知（零配置，默认走这条）+ 报告转两三行
│   └── uvfetch.mjs                   # 机器上没有 uv/python 时自动下一份
├── prompts/
│   ├── duty.md                       # 一轮的章程（判据 + 红线 + 报告格式）
│   └── sample-candidates.json        # 内置示例（manual 模式开箱即用）
└── vendor/douyin-mcp/                # 内置 Python MCP（FastMCP + stdio）
    ├── mcp_server.py                 # 工具注册 + 白名单
    ├── prescreen.py                  # ⭐ 判断层第一道闸：预筛 + 比值 + 证据包
    ├── comment_executor.py           # 评论执行器（四档 + 唯一配额闸）
    └── drivers/
        ├── router.py                 # 按配置选后端
        ├── driver_bbbrowser.py       # ⭐ 默认：bb-browser 遥控本机 Chrome
        ├── driver_browser.py         # Playwright 独立浏览器
        ├── driver_cookie.py          # Cookie + HTTP 直连
        └── driver_manual.py          # 手动喂料（带示例兜底）
```
